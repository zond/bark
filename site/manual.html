Words used here

  • Node: the small radio device. Each has an ID of twelve letters and digits, shown on its screen, such as BAE6E6CBF4F5.
  • Relay: a node that passes on other people's messages. A node on a charger is a relay.
  • Sleepy node: a node saving its battery. It sleeps most of the time and talks through one relay near it, its anchor.
  • Address: a node's place and its ID. Messages are sent to an address.
  • Card: what you give someone so they can write to you. It holds your name, your key and the address to reach you at. It is shown as a QR code.
  • Home node: a node that stays in one place on power and keeps your messages until you fetch them.
  • Owner: the one person who decides who else may have a home on a node.
  • Public node: a node that anyone nearby may use from the app. Every node is public until its people make it private.
  • Paired: your phone and a node know each other, after you typed the code from the node's screen once.

What you need

  • A LILYGO T-Echo for 433 MHz with its antenna. Or no node at all, if a public node is near you.
  • A USB cable and, for a relay, a charger.
  • An Android phone.

Setting up a node

Before anything else, screw on the antenna. A radio that sends without one can be damaged.

Put the software on it. A new T-Echo comes with other software. To replace it:

  1. Download bark.uf2 from the latest release.
  2. Connect the node to a computer with the USB cable. If nothing happens with a cable that has the small plug at both ends, try one with the larger, flat plug at the computer's end.
  3. Press the reset button, the upper one on the node's side, twice quickly. A drive named TECHOBOOT appears on the computer.
  4. Copy bark.uf2 to that drive. The drive disappears and the node restarts. Some computers show an error as it disappears; ignore it.

The screen now shows a QR code with the node's ID under it. You do this once: later versions arrive by themselves (Updates).

Give it a place. A node must know where it stands, because addresses are places. It finds out from its GPS, which needs a view of the sky and may take some minutes the first time. Indoors, or to be exact, set the place from the app instead: Settings, This node, Place.

Give it power. The node chooses what it is by its power and by whether it moves:

  • On a charger it is a relay, and helps everyone around it.
  • On battery, standing still, it goes on relaying until the battery is low, then turns sleepy. This is on purpose: when the power goes out, the relays of a whole district lose it together, and the network must not go with it. A full battery relays for about four days.
  • On battery, carried, it is sleepy.

A sleepy node passes on nobody else's messages. The one exception is when it hears no relay at all: then sleepy nodes pass messages among themselves, slowly, until a relay turns up.

To choose yourself, hold the lower button for 3 seconds: it switches the node between relay and sleepy (the screen and buttons). A pocket node that lies still for long, on a desk or in a drawer, counts as standing still and relays; make it sleepy this way if you would rather keep its battery for yourself.

The node's screen and buttons

The node has two buttons on its side. A small label on the screen points at each.

  • The upper button restarts the node. Pressed twice quickly, it opens the drive for new software instead.
  • The lower button, pressed briefly, switches the screen between the QR code and the node's state, which stays for 30 seconds.
  • The lower button, held 3 seconds, switches the node between relay and sleepy, whatever its power. It stays so until you plug the cable in or pull it out.

The QR code leads to the project's page, where anyone can get the app. Under it is the node's ID. While a phone pairs, the pairing code is shown there instead.

The state has a line for each of these:

Line Meaning
FIXED RELAY, CARRIED RELAY, RELAY NO PLACE a relay: standing still, being carried, or not yet knowing its place
SLEEPY ANCHORED, SLEEPY NO ANCHOR a sleepy node: with a relay to talk through, or still looking for one
STARTING just switched on, listening before it joins
ID the node's ID
NODE V47 the version of its software
GET V48 14/31 it is receiving a new version, and how far it has come
PHONE UNPAIRED, PUBLIC, PRIVATE, 3 PHONES who may use it
PAIR CODE the code to type in the app
CONFIRM a code to type in the app when you remove a phone or change the owner
PHONES FULL eight phones are paired, and there is room for no more
KNOWN 5/4/2 other nodes it hears now, how many of them clearly, and how many of those have taken a message from it
POWER USB or BATTERY 73%/9D its power, and on battery about how long it lasts as it runs now
UP how long since it was switched on
TIME the time when the screen was drawn

The screen keeps its picture when the node is off. If a press changes nothing within a few seconds, the node is not running.

Installing the app

Open the front page on the phone, or scan the code on any node's screen, and tap Get the app. Android asks once whether your browser may install apps.

At the first start the app asks for Bluetooth, which is how it reaches a node. A Get started card then lists three steps:

  1. Set your name. It goes on your card.
  2. Find a node. See the next section.
  3. Add a first contact.

The app also makes your 12 words. They are your identity. Write them down and keep them safe: if you lose the phone, they are the only way back (Backup).

Connecting to a node

The app looks for a node by itself, over Bluetooth, which reaches a room or two.

  • A public node: nothing to do. With no node of your own in reach, the app finds a public node nearby and uses it as a guest. No code is needed. It connects for a moment whenever it has something to send or collect, so that other guests get their turn.
  • Your own node: pair with it, once. Open Settings, Node, tap Scan, and tap Pair beside your node. Its screen shows a six-digit code; type it in the app. From then on the app connects to it whenever it is near, and prefers it to any public node. A node takes up to eight paired phones, and a phone can be paired with several nodes.

The same list shows every node in reach with its signal, if you want to choose one yourself: tap a public node to use it as a guest.

A line at the top of the first screen always says where you stand, for example "Connected to your home", "Connected to ID … as a guest" or "Not connected. Texts wait on the phone". Tap the small info button beside it to learn why.

You do not need to be connected to write. Messages wait on the phone and go out when a node is next in reach.

Contacts and cards

To write to someone you need their card, and they need yours to answer.

  • Show yours: the QR button opens My card. Let the other person scan it, or tap Share to send it some other way.
  • Take theirs: Scan their card with the camera, or paste a card you were sent, under Contacts.

A card says where to reach its person. With a home node it stays good for as long as that home stands. Without one the card is marked temporary: it names the node you used last, which helps only while you keep coming back to it.

When your card changes, for example after you choose a new home, the app tells you and offers Send my card. It never sends your card by itself.

A person who writes to you before you have their card shows as not verified: the app cannot yet know they are who they say.

Swipe a contact or a conversation aside to archive it. Archived ones are kept under Archived and come back when the person writes.

Writing and reading messages

Open a conversation, write, send. Small marks under each message tell its story; tap the message for an explanation of every mark.

A message you sent shows, in turn:

  • a clock: waiting on the phone for a node;
  • two arrows: being handed to the node;
  • a check: the network has taken it.

The check does not mean it has arrived. The network sends no news of arrival; you know it came when the person answers.

If the network is busy it gives the message back, and the app says "The network is busy, sending again in …" and tries again by itself. Nothing the network has taken is thrown away for being old.

Long messages. A single message holds about 200 letters, fewer in scripts that take more room for each letter. A longer text is sent in parts, up to 16, and shown as one message. The app says how many parts before you send.

Reactions. Press and hold a message you received to answer with an emoji. The sender sees it on their message.

Where a message goes. To the address on the person's card: their home, if they have one. But each message also carries, encrypted, the address of the node its sender wrote from, so a quick reply goes straight to where they are.

Your home node

Without a home, messages for you go to the node you last used and wait there. That works for someone who always uses the same node. If you move around, set a home.

A home must stay in one place, on power, and know its place. A node in your window on a charger is the usual choice.

  • Set it: connect to the node, then Settings, Home node, Set home. If you were using it as a guest, you pair first. Your card changes, so send it to your contacts when the app offers.
  • Read your mail at home: when the phone is connected to your home, messages arrive by themselves.
  • Read your mail away from home: tap the inbox button, Fetch my mail. The request travels to your home and the messages travel back to the node you are on. This can take up to about half an hour on a large network; the button shows that it is waiting.
  • Change or remove it: Set home on another node, or Remove home. Your old home sends you what it still keeps, then forgets you. If it was out of reach just then, the app finishes the job the next time your phone is connected to it.
  • After restoring your identity on a new phone: Use my existing home, and give the home's address.

Sharing a node with others

Public or private. Under Settings, This node, the switch Public decides whether phones that are not paired may use the node as guests. It is on from the start.

The phones at a node. The same place lists every phone paired with the node and every person with a home there. From here you can Unpair your own phone, or remove someone else's; the node then shows a CONFIRM code to type, so that only someone standing at the node can do it.

The owner. The first person to make a node their home becomes its owner. The owner can, from anywhere:

  • give a contact a home on the node: Share my home node in that conversation's menu;
  • see who has a home there, and remove one: Settings, Home node, People with a home here;
  • make someone else the owner.

If a node has no owner, a person whose home it is can press Become owner while connected to it. A node holds the homes of up to eight people.

The map of nearby nodes

Nearby nodes, in the menu, shows the node you are connected to and the nodes it hears, on a street map. The map itself needs the internet; the nodes are shown without it.

The line to each node is green, amber or red for a good, fair or fragile radio link. Tap a node for what is known of it: relay or sleepy, fixed or carried, its place, its power, how well it is heard, when it was last heard, its software's version, and which of your contacts were last seen there.

A sleepy node hears little besides its anchor, so the map from a pocket node is nearly empty. That is normal.

Updates

The app. When a newer version is out and the phone has internet, a bar at the top says so. Tap it to install.

A node, by itself. A node that hears a neighbour with a newer version collects it over the radio, piece by piece, checks that the project signed it, and restarts into it. While it collects, it already passes the pieces it has on to its own neighbours. Nothing needs to be done. It takes a few hours for a relay and most of a day for a sleepy node. Pairings, homes and stored mail are kept. A node on a low battery waits until it has power.

A node, from the phone. To start a new version off, or to hurry: Settings, Updates, Send to the node, then Reboot into version …. The transfer takes under a minute and the restart about another.

A node takes only software signed by the project, and only a version newer than its own. If a new version fails to start properly, the node goes back to the one before.

Backup and moving to a new phone

  • The 12 words bring back your identity, so people can still reach you with the card they have. They do not bring back contacts or messages. See and restore them under Settings, Backup.
  • The identity file brings everything: identity, contacts and, if you tick the box, messages. Settings, My identity, Save to a file, with a password of your choosing; on the new phone, Restore from a file.

Use an identity on one phone at a time. After moving, pair the new phone with your nodes again: a pairing belongs to the phone and does not move.

Running in the background

The app keeps its connection with the screen off, and shows a notification saying which node it is on. New messages are announced like in any messenger.

Some phones stop apps to save battery. If messages only arrive when you open the app, go to Settings, Battery, Let bark run.

Where to put nodes

  • High and in the open is what counts. A node on a roof or in an upstairs window reaches far more neighbours than one on a desk. Radio at this frequency goes through a wall or two but not through a hill.
  • A relay at home, a node in the pocket is the usual pair: the relay is your home and helps the neighbourhood; the pocket node is your way in wherever you are.
  • Outdoors, keep it dry. A case that lets you reach the buttons and see the screen saves trouble later.
  • A public node suits a place people visit: put it where its screen can be seen, since the code on it is how people get the app.

A network grows by relays within reach of each other. One node alone can do nothing but wait.

Privacy and limits

  • Only the recipient can read a message. The app encrypts it for them alone, and no node on the way can open it.
  • Places are not private. Anyone with a radio in range learns each node's ID and where it stands. Someone listening near your home node may work out that your mail passes through it.
  • The network trusts every node. It was built for when infrastructure fails, not to resist an attacker. Someone who wants to disturb the nodes around them can.
  • It shares the air fairly. The law limits how much each node may send, so the network carries short texts and refuses more when it is full, telling the app when to try again.
  • Android only, for now.

When something does not work

What you see What to try
No node found in the scan Go closer; Bluetooth reaches a room or two. Check that the node runs: press its lower button and see whether the screen changes.
RELAY NO PLACE on the node It has no GPS fix. Give it a view of the sky, or set its place in the app.
SLEEPY NO ANCHOR It hears no relay. Move nearer to one, or plug it in to make it a relay.
"Does not know this phone" The node forgot the pairing. Tap Pair again.
"Needs an update" beside a node The node's software is too old for this app. Send it the new version over USB, as when setting it up.
A sent message stays on the clock No node is in reach. It goes when one is.
"Your home did not answer your last fetch" The home is off or out of reach. Try again later; if it never answers, set another home.
A node will not take the TECHOBOOT step Press the upper button twice, faster.

The app's menu has a Debug screen with a log of what the app and the node said to each other. It is the first thing to look at, and to send along, when reporting a fault.

For the curious

Things in the project that most people never need:

  • bark, a command-line phone. Everything the app does over Bluetooth, from a Linux computer (bark-cli/README.md).
  • The simulator. Runs the same software as the nodes for a whole city at once, tens of thousands of nodes, to test the design before hardware does (docs/simulator-design.md).
  • The loader. A small program on each node that swaps a new version in and the old one back if the new one fails (bark-fw/README.md, "Updates").
  • The bench tools. Scripts and special builds for measuring radios and running tests on real boards (bark-fw/README.md).
  • The specification and the decisions. Every rule the nodes follow is in docs/protocol.md, and every choice with its reason in docs/roadmap.md.

How to build all of it: DEVELOPING.md.
